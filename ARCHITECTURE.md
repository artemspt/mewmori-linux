# Мяумори — архитектура

Пиксельный кот, который живёт на рабочем столе KDE, комментирует происходящее
и умеет спать в лежанке-виджете панели. Порт идеи macOS-приложения Mewmori на
Linux: от оригинала взяты только графические ассеты, весь код написан заново.

Сторонних Python-пакетов **нет**: только `gi` (PyGObject) и `cairo`, которые уже
есть в системе. Всё остальное — стандартная библиотека, включая распаковку
LZ4 для файла сессии Firefox.

Исключения — только две необязательные половины: телеграм (§9) хочет
`telethon`, голос (§10) хочет `faster-whisper`, `sounddevice`, `numpy` и
`pynput`. Ни того, ни другого нет — кот запускается, рисует, говорит и всё
замечает как прежде, а недостающая часть сообщает, чего ей не хватает.

## 1. Три процесса

```
┌──────────────────────────┐        D-Bus         ┌────────────────────────┐
│  Кот (GTK3, Python)      │◄────────────────────►│  Плазмоид (QML)        │
│  mewmori/                │  org.mewmori.Cat     │  com.mewmori.bed       │
│                          │                      │  живёт в панели KDE    │
│  окно поверх всех окон,  │  ◄── файл состояния  │                        │
│  прозрачное, X11         │      ~/.cache/...    │                        │
└───────────┬──────────────┘                      └────────────────────────┘
            │ HTTP на 127.0.0.1:11434
            ▼
┌──────────────────────────┐
│  ollama                  │   одна модель на всё (см. §4)
└──────────────────────────┘
```

Почему именно так: плазмоид нельзя написать на GTK — панель KDE принимает только
QML-виджеты. А кота нельзя сделать плазмоидом: ему нужно свободно ходить по
всему экрану поверх окон. Поэтому два процесса и мост между ними.

### Мост кот ↔ лежанка

| Направление | Чем | Почему так |
|---|---|---|
| Плазмоид → кот | D-Bus, методы `SetBedRect`, `WakeUp`, `PutToBed` | Аплет сам сообщает свои экранные координаты — иначе кот не поймёт, что его на него перетащили |
| Кот → плазмоид | файл `~/.cache/mewmori/state` (`0`/`1`/пусто) | QML **не может** подписаться на сигналы D-Bus без плагина на C++. Файл читается через `cat` в `Plasma5Support.DataSource` раз в секунду |

Ловушка, на которую я потратил время: QML по умолчанию запрещает читать
локальные файлы через `XMLHttpRequest` (нужен `QML_XHR_ALLOW_FILE_READ=1`,
на который внутри plasmashell полагаться нельзя). Отсюда чтение через `cat`.

## 3. Анимация

Ассеты оригинала оказались **декларативной скелетной анимацией**, а не
спрайт-листами. Это главная находка проекта: движок пришлось написать, зато
весь контент достался готовым.

```
assets/
  skins/<14 скинов>/skin.json     риг: части, родители, якоря, позиции
                   *.png          body, head, tail, eye, pupil + варианты головы
  animation/
    animations.json               19 состояний: базовые клипы с весами,
                                  оверлеи, «перебивки», реакции
    clips/<33 клипа>.json         дорожки ключевых кадров
  cosmetics/<22 предмета>/        крепления к голове/телу/хвосту (пока не задействованы)
```

**Формат клипа.** Дорожка это `(часть, свойство, ключевые кадры, easing)`.
Свойства — `x, y, rotation, scale, scaleX, scaleY, alpha` — всегда **дельты**:
ноль для сдвигов и поворота, ноль вокруг единицы для масштаба и прозрачности.
Отдельный вид дорожки — покадровая смена текстуры (`frames` + `fps`), так
сделаны говорящий рот, зевок и умывание.

**Сборка позы** (`rig.Animator.update`):

1. базовый клип состояния (выбирается по весам),
2. предыдущий базовый, если идёт переход — блендится по `blendIn`,
3. оверлеи состояния — дыхание, моргание, хвост, уши — складываются аддитивно,
4. `extra`-оверлеи, переживающие смену состояния: так работает рот во время речи,
5. «перебивки» в простое: раз в 7–16 секунд кот умывается, зевает, потягивается.

**Отрисовка** (`render.draw`): иерархия трансформов → матрицы cairo → сортировка
по `z` → рисование. Прозрачность наследуется от родителя, поэтому закрытый глаз
прячет и зрачок.

Три неочевидные вещи:

- Оси рига направлены вверх, cairo — вниз. Переворот делается один раз, при этом
  инвертируется и знак угла поворота.
- `pixelsPerUnit = 10.486`, `referenceHeight = 100`. Арт нарисован по сетке
  **25 px на пиксель** — тело это 21×18 логических пикселей. Из этого считается
  масштаб всего остального, включая лежанку.
- Габариты считаются по **непрозрачным** пикселям (`render.ink_box`), а не по
  прямоугольникам текстур: у 5 из 14 скинов в текстуре головы до 100 px пустых
  полей, и без обрезки кот висел бы над поверхностью.

## 4. Одна модель

Локально, через ollama на `127.0.0.1`. Наружу не уходит ничего.

Моделей было две: быстрая говорила, сильная — прибитая к CPU — читала код,
пока никто не смотрит, и писала находки в дневник. Этого больше нет. Кот не
пишет отчётов о проекте: он замечает и запоминает, как животное, а не как
аналитик. Вместе с разбором ушёл и весь класс проблем — две модели в одной
памяти, просадка говорящей с 6.0 до 2.2 tok/s каждый раз, когда просыпалась
вторая.

Зрение осталось отдельным: снимок экрана смотрит модель с проектором.

**Квантование слышно на именах.** `iq2` называл Kanye West «Кенни» —
полувспомнил и дописал сам. Четырёхбитная версия тех же весов говорит «Канье».
Поэтому выбор по умолчанию предпочитает четыре бита двум, даже ценой скорости.

### Чем оплачена задержка и что с ней сделано

Замерено на `qwen3.8:27b` (13 ГБ в карте на 12 ГБ, 38% слоёв на CPU):

| | Токенов в промпте | Префилл |
|---|---|---|
| system меняется каждый раз | 378 | 5.3 с |
| system один и тот же, второй запрос | 369 | 3.2 с |
| короткий system | **113** | 4.9 с |

**Укорачивание промпта не помогает** — 113 токенов обрабатывались столько же,
сколько 378. Префилл упирается не в длину, а в фиксированную цену прохода по
слоям, лежащим на процессоре.

**Помогает стабильный префикс.** ollama переиспользует KV-кэш для той части
запроса, которая совпала с предыдущим, а system-сообщение стоит в самом начале.
Настроение кота, подмешанное в конец system, обнуляло весь кэш на каждой
реплике. Теперь всё, что меняется от реплики к реплике — настроение, вспомненные
факты, — уходит в **пользовательский** ход, после общего префикса. Измерено на
живом коте: **6.2 с на холодную, 1.3 с при повторе**.

**А ещё пузырь не появляется, пока не пришёл первый настоящий токен.** Пустое
облачко с мигающим курсором, висящее ровно те секунды, что модель читает
промпт, только рекламирует, насколько она медленная. Появляясь уже с первым
словом, оно читается как мгновенный ответ. Рот кот тоже открывает не раньше.

Модель переопределяется `MEWMORI_MODEL` и переключается в меню и настройках.

**Оборванный ответ подрезается по границе фразы.** Лимит `num_predict`
останавливает модель не там, где кончилась мысль, а на очередном токене —
обычно посреди слова: «…в общем, ничего особ». Если ollama сообщила
`done_reason: length`, `chat.tidy` откатывает текст к последней законченной
фразе, а если и её нет — отбрасывает недопечатанное слово. Кот, оборвавший
себя на полуслове, читается как поломка, потому что это она и есть.

## 5. Что кот знает

| Источник | Как добывается | Что даёт |
|---|---|---|
| IDE и проект | `recentProjects.xml` + время изменения `.idea/` | Путь проекта, открытый файл, дерево, языки, документация, исходник открытого файла |
| Программы | `argv[0]` процессов в `/proc` | Каталог из 8 знакомых программ с описанием, что каждая значит |
| Музыка | MPRIS по D-Bus | Артист, название, альбом; реклама Spotify отсеивается |
| Экран | `Gdk.pixbuf_get_from_window` | Снимок в память, ужатый до 1024 px, **на диск не пишется**. Увиденное идёт и в дневник, и вслух |
| Присутствие | `org.kde.screensaver.GetSessionIdleTime` | Секунды без ввода |
| Нагрузка | `/proc/stat` минус процессы ollama | Чужая загрузка CPU |
| Браузер | `recovery.jsonlz4` сессии Firefox + заголовки окон | Все открытые вкладки, домены и что каждый сайт значит |
| Уведомления | `dbus-monitor` на `org.freedesktop.Notifications` | Кто и о чём написал, и насколько это срочно |
| Claude Code | файл состояния, который пишут его же хуки | Работает / ждёт ответа / закончил |
| Железо | `/proc/meminfo`, `statvfs`, `/proc/loadavg` | Диск, память, swap, нагрузка, батарея |
| Другие машины | те же файлы через один `ssh` | То же самое про сервер |

Три ловушки, стоившие отладки:

- **Сопоставление по всей командной строке ловит само себя.** Поиск «pycharm»
  в `/proc/*/cmdline` считал IDE запущенной, если это слово просто встречалось в
  команде терминала — включая мой собственный диагностический скрипт. Сравнение
  идёт по `argv[0]`, а шаблоны привязаны к сегментам пути: `/pycharm/` совпадает
  с `/opt/pycharm/jbr/bin/java`, но не с `~/PycharmProjects/...`.
- **Обрезанное дерево порождает выдумки.** Папка, попавшая в список голым именем,
  читается моделью как пустая. Поэтому каталоги за пределом глубины помечаются
  количеством файлов: `assets/animation/clips/ (33 файлов)`.
- **`select()` не видит буфер Python.** Уведомление — это вызов метода к панели,
  а не сигнал, поэтому подписаться на него нельзя, шину приходится слушать
  через `dbus-monitor`. Одно сообщение занимает много строк, и конец его виден
  только по паузе в выводе — а `select()` по паузе не срабатывал, потому что
  `readline()` уже утащил остаток сообщения во внутренний буфер, где ядру его
  не видно. Читается сырой дескриптор, строки режутся вручную.

### Другие машины

`~/.config/mewmori/hosts.json`, права 0600:

```json
[{"name": "веярон", "host": "veyron"},
 {"name": "вишня", "host": "artem@vishnya.veyron.online", "password": "…"}]
```

Правится в настройках: Другие машины → «Список машин…», там же кнопка
«Проверить», которая делает один заход и показывает, что ответила машина.
Файл — просто то, где это лежит.

Хост, уже описанный в `~/.ssh/config`, не требует здесь ничего, кроме имени.
Пароль (если ключа нет) уходит в ssh через `SSH_ASKPASS` — в аргументах команды
он не появляется, и в `/proc` его не видно; в файле он всё же лежит открытым,
поэтому ключ лучше. Опрос — один `ssh` раз в пять минут, в отдельном потоке:
кадры на него не ждут.

## 6. Цикл присутствия

```
хозяин работает
      │  5 минут без ввода
      ▼
«Ты всё ещё здесь?»            ← быстрая модель
      │  ещё 90 секунд тишины
      ▼
считается, что ушёл  ──►  выжимает из дня факты в картотеку
      │                   и сжимает закончившуюся неделю (§7)
      │                   спонтанные реплики отключены:
      │                   слушать всё равно некому
      │  движение мыши
      ▼
«вернулся» ──► отдаёт то, что накопилось, пока тебя не было
```

Взгляд на экран тоже событийный, а не по таймеру: он случается, когда
запустилась новая программа либо прошёл случайный промежуток 7–18 минут, и
только если кот стоит на месте, чужая загрузка CPU ниже 60% и с прошлого раза
прошло не меньше 5 минут.

### Кот уступает видеопамять

Процессор — неверный свидетель. Майнкрафт спокойно живёт на 50% CPU, а ломается
всё от другого: включаешь шейдеры, и им негде разместиться, потому что
одиннадцать гигабайт видеопамяти держит языковая модель.

Поэтому вопрос не «сколько занят процессор», а «нужна ли карта кому-то ещё».
Ответ — да, если впереди игра, либо если карта почти полна и это **не наша**
модель.

Тогда кот говорит, что ресурсов не хватает, **выгружает модель из ollama**
(`keep_alive: 0` — единственное, что действительно возвращает память) и уходит
спать в случайный угол, пока карта не освободится. Сам кот при этом остаётся на
экране и продолжает ходить: спрайт не стоит ничего, а исчезающее окно выглядит
поломкой.

Фраза перед сном — фиксированная, не от модели. Сочинить её было бы нечем:
это последнее, что происходит до выгрузки.

Раньше на этом месте было «спрятать окно и остановить кадры». Оно освобождало
пару мегабайт GTK и ни одного гигабайта из тех, ради которых затевалось, — а
две проверки на полноэкранность не срабатывали никогда: одна спрашивала о
полноэкранности **собственное окно кота** (оно `DOCK` и таким не бывает), вторая
читала поле `fullscreen`, которого у `apps.App` нет.

Выгрузить руками — пункт «Освободить видеопамять» в меню.

### Кто первый занял карту

Слушать имя нужно постоянно — проход раз в секунду. Замерено на модели `small`:
**0.01 с на видеокарте против 1.05 с на процессоре**, а `medium` на процессоре
и вовсе 3.18 с, то есть проходы начинают копиться быстрее, чем успевают идти.

Влезть при этом некуда: ollama держит тринадцатигигабайтную модель в
двенадцатигигабайтной карте. Поэтому при неудаче кот **сам разнимает своих
двоих**: слух просит полгигабайта и просит их постоянно, речь просит всё и
просит редко — и всё равно перезагрузится на следующей реплике. Языковую
модель просят выйти один раз, слух заходит первым.

### Напоминания

«кот, сегодня в 15 часов мне нужно выпить таблетку» разбирается регулярками, а
не моделью: модель на процессоре думает секунды, а сказавший «через десять
минут» имеет в виду именно десять минут, — и ошибка на час здесь означает
пропущенную таблетку.

Нужны обе половины: и время, и намерение. «В 15 часов созвон прошёл ужасно» —
это рассказ, а не просьба разбудить, и напоминанием не становится.

Срабатывает дважды: за пять минут и ровно в срок, каждое ровно по одному разу —
флаг записывается на диск сразу, иначе то же самое прозвучало бы снова через
минуту.

Отдельный повод, не связанный со временем: если программы закрываются пачкой,
компьютер сейчас выключат, и всё назначенное на ближайший час говорится сразу —
через пять минут будет некому.

**Порог по процессору вычитает саму ollama.** Иначе сильная модель, загружающая
все ядра, держала бы систему «занятой» вечно и кот заглушил бы сам себя.
Явно набранный вопрос через порог проходит всегда.

### Кто может перебить

Источников событий много — программа открылась или закрылась, песня, вкладка,
уведомление, Клод, диск. Поэтому под всеми ними один общий пол: между
спонтанными репликами не меньше 75 секунд, независимо от того, кто их поднял.
Без него кот перестаёт быть котом и становится демоном уведомлений.

Важное этот пол не проходит, а ставит: про кончающийся диск, про вопрос от
Клода и про пришедшие сообщения кот говорит даже когда машина занята, — но
следующие 40 секунд после этого молчит обо всём остальном.

Пол начинался с 75 секунд и оказался слишком высоким: источников много, все
они делят одну очередь, и музыка с экраном оказывались вечно за чужой спиной.
Сейчас 40, и это настройка, а не константа.

**Уведомления не доставляются сразу.** Они копятся, пока хозяин печатает, и
отдаются на ближайшей паузе: 20 секунд без ввода, либо когда что-то закончилось
(Клод доработал, программа закрылась, хозяин вернулся), либо через 10 минут
ожидания. Помеченное как критическое идёт мимо очереди. Если хозяин ушёл —
копятся дальше: говорить в пустоту незачем.

## 7. Дневник и память

```
~/.local/share/mewmori/
  cards.json                 колода слов: сторона, перевод, коробка, срок
  screentime/2026-08-23.json сколько секунд сегодня ушло в какую программу
  journal/2026-08-19.md      записи с отметкой времени: «— экран», «— хозяин сказал»
  journal/weekly/2026-W33.md неделя, сжатая в несколько предложений
  knowledge/лонер.md         датированные факты по темам, с [[ссылками]]
  projects/<путь>.md         постоянное понимание каждого проекта
  session.json               последние несколько реплик разговора
  telegram.session           вход в телеграм (не выкладывать никуда)
~/.config/mewmori/
  settings.json              всё из окна настроек
  hosts.json                 другие машины, 0600
  telegram.json              api_id/api_hash, 0600
~/.cache/mewmori/state       0 / 1 / пусто — для плазмоида
~/.cache/mewmori/launch      путь к run.sh — чтобы лежанка могла запустить кота
```

Тему записи выбирает модель, путь выбирает код: за пределы этой папки писать
нельзя.

Память четырёхслойная, и слои разные не случайно.

| Слой | Что | Живёт |
|---|---|---|
| `session.json` | последние 8 реплик дословно | 12 часов |
| `journal/<дата>.md` | всё, что кот заметил за день | 3 дня как контекст |
| `journal/weekly/<год>-W<неделя>.md` | неделя, сжатая в 3–5 предложений | всегда |
| `knowledge/<тема>.md` | датированные факты по темам | всегда |

Короткий слой нужен, чтобы перезапущенный кот не здоровался с хозяином как с
незнакомцем; старше двенадцати часов он не поднимается — подхватить вчерашнюю
фразу хуже, чем начать заново.

**В историю попадает только то, что сказал хозяин.** Всё остальное, что уходит
в модель, — это подсказки самому коту: «Пора: «созвон». Скажи ему об этом одной
фразой». Лёжа в истории наравне с репликами, такая строка попадала в промпт
следующих шести ответов, и кот читал собственную подсказку как часть разговора —
одно напоминание превращалось в пять упоминаний созвона, который давно прошёл.
Ответы кота в истории остаются: они нужны, чтобы он не повторял сам себя.

**До картотеки кот не записывал ровно одного: того, что говорит хозяин.** Экран,
железо, Клод, разборы проекта — всё было, а слова человека жили только в
`session.json` и умирали через полдня. Теперь то, что хозяин сказал сам —
напечатал или произнёс, — попадает в дневник, и именно из него потом выжимаются
факты.

### Картотека

Раз в сутки, в том же разборе «когда хозяина нет» (§6), сильная модель
перечитывает день и выписывает то, что стоит помнить долго: `тема | факт`.
Сиюминутное — какая играла песня, сколько было места на диске — отбрасывается
явным указанием: через неделю оно неинтересно.

Хранится markdown-ом с `[[вики-ссылками]]`, поэтому папка открывается в
Obsidian как настоящий граф — его можно листать, искать ветку и править руками.

**Кот по этому графу не ходит.** На каждую реплику ему нужно ответить на один
вопрос: какие три факта сейчас уместны, — и уложить их в пару сотен символов
промпта, потому что быстрая модель читает на CPU. Это ранжирование, а не обход,
и рёбра для него не нужны. Ссылки существуют для человека; строить и чинить
граф силами модели на 2 токенах в секунду означало бы получить красивый граф,
который врёт.

Ранжирование — совпадение слов плюс свежесть, без зависимостей и эмбеддингов.
Словоформы сравниваются по общей основе (`майнкрафт` ≈ `майнкрафтом`): грубо,
но ошибается в сторону «не нашёл», а для памяти это безопасная сторона. Свежесть
не отсекает, а притеняет — сказанное полгода назад всплывёт, если оно ровно по
теме. Слова, которые есть в каждом факте (`хозяин`, `кот`), выброшены: по ним
ранжировать нечего.

Каждый факт отдаётся модели с датой, переведённой в человеческое: «вчера», «три
недели назад». Без этого кот вечно припоминал бы, что хозяин собирается купить
сервер, — уже год как купленный.

### Картотека резала сама себя

Тему записи выбирает модель, и каждую ночь она выбирает для одного и того же
новое слово: `инструмент` и `инструменты`, `сервер` и `серверы`, `hobby` и
`хобби` — каждое стало отдельным файлом с одним фактом, пересказывающим
соседний. Тридцать две темы на пятьдесят семь фактов — это не богатая память,
это одна память, порезанная на куски.

Ломается от этого не хранилище, а ответ. `recall` кладёт в промпт три факта, и
все три оказывались одним и тем же, сказанным трижды. Кот при этом выглядит
именно так, как о нём и сказали: тупит.

Чинится в двух местах. **Тема приклеивается к существующей**, если основы
совпадают — тем же сравнением по основе, что уже стояло в ранжировании.
**Факт не пишется, если он пересказ**: совпадение множеств слов по Жаккару,
порог 0.6. Порог намеренно высокий — слить два разных факта значит потерять
память, а оставить лишний дубль значит потратить один слот.

Накопленное до этого разбирает `knowledge.tidy()` — кнопка «Прибраться» в
настройках. Из живой картотеки она слила три темы и выбросила восемь
пересказов; переживший дубль сохраняет **раннюю** дату — когда об этом сказали
впервые.

Что она не ловит: `hobby` и `хобби`. Сравнение по основе через алфавиты не
ходит, а словарь переводов ради двух файлов — это уже не картотека.

### Карточки слов

Отдельно от картотеки, и намеренно. Факт там — то, что кот знает про хозяина и
может к слову вспомнить; карточка — то, что хозяин учит, и ей нужны расписание,
счёт и дата следующего показа, которых датированной строчке markdown держать
негде.

Расписание — Лейтнер: пять чисел и ни одной зависимости. Ответил верно —
коробка выше и возврат позже (0, 1, 3, 7, 16, 35 дней), ошибся — **сразу в
первую**, а не на шаг вниз: слово, которое ты только что забыл, не «почти
выучено», и шаг вниз показал бы его завтра, а не сегодня, когда оно ещё
забывается. Настоящий интервальный повтор (SM-2, FSRS) подбирает интервалы под
карточку по истории ответов — это стоит иметь на тысячах карточек и годах
данных, и не стоит ничего на двадцати.

**Карточка рисуется в cairo, а не собирается из виджетов**, потому что
переворот должен быть переворотом. Перекрёстное затухание между двумя
`Gtk.Label` читается как подмена страницы; сжатие карточки в ноль по
горизонтали, смена лица ровно в тот кадр, когда ширины нет, и раскрытие обратно
читается как кусок картона, повернувшийся в руке.

Две ловушки, обе видны только на кадре в середине переворота:

- **Pango меряет в том пространстве, которое ему дали.** Лицо, нарисованное
  внутри уже сжатого контекста, переносит текст по-новому на каждом кадре —
  `serendi-pity` посреди оборота. Лицо рисуется в свою поверхность прямо, и
  сжимается уже готовая картинка.
- **Фаза замыкается в круг.** Проверка «пора остановиться» стояла после
  арифметики шага, а на шаге `2 × FLIP_STEPS` та же арифметика снова говорит
  «переверни лицо» — и карточка честно переворачивалась обратно.

Слово заводится голосом или из окна: «запомни слово brittle». Перевод можно не
диктовать — пустую сторону заполнит модель, но карточка создаётся в любом
случае: слово, потерянное потому, что ollama не отвечала, хуже карточки с
пустой оборотной стороной, которую можно дописать руками.

### Чем считается расписание

Anki здесь был, и его нет. Нужна была не программа, а её механика, и механика
переехала внутрь: **FSRS-6**, тот же алгоритм, что Anki считает по умолчанию.

Три предыдущих подхода и почему каждый мало:

| | Что помнит о карточке | Чего не видит |
|---|---|---|
| Лейтнер | номер коробки | что слова разные |
| SM-2 (1987) | коэффициент лёгкости | *когда* ты ответил |
| FSRS | стабильность, трудность | — |

FSRS — модель DSR: **стабильность** (за сколько дней вероятность вспомнить
падает до 90%), **трудность** (1..10, насколько слово тяжело лично тебе) и
**вспоминаемость** (шанс вспомнить прямо сейчас, по кривой забывания). Двадцать
один вес, обученный на сотнях миллионов настоящих повторов, — а не числа,
придуманные из головы.

Главное отличие от всего, что было до: **новая стабильность зависит от того, в
каком состоянии память была в момент ответа.** Слово, вспомненное на грани
забывания, укрепляется куда сильнее, чем оно же, повторённое на следующий день.
Ни коробки, ни SM-2 этой разницы не видят вовсе — они смотрят только на то,
*как* ты ответил, но не *когда*.

**Четыре кнопки, а не две.** «Знаю / не знаю» выбрасывает ровно ту информацию,
из которой модель и считает: между «не помню» и «вспомнил сразу» лежат «еле
вспомнил» и «вспомнил», и это разные будущие для одного и того же слова. Каждая
кнопка подписана тем, что она сделает, — кнопка, не говорящая, куда отправит
карточку, нажимается наугад.

Веса и формулы **сверены с исходником** `open-spaced-repetition/py-fsrs`, а не
взяты по памяти: одна перепутанная степень здесь — это не ошибка на день, а
карточки, которые молча приходят не тогда, и заметить это по ощущениям нельзя.
Проверка на это есть прямая: при удержании 0.9 интервал обязан равняться самой
стабильности — это её определение, и на нём ловится любая путаница в знаках.

Точки под карточкой — не коробка, а вспоминаемость: сколько слова в памяти
прямо сейчас. Между показами она тает.

# ponytail: только дневная часть, без внутридневных шагов обучения (1 мин,
# 10 мин). Поэтому «не помню» и «еле вспомнил» на новой карточке дают один и
# тот же завтрашний день — в Anki на этом месте сессия дозубривания, а кот
# показывает карточки раз в день, а не гоняет до запоминания.

Веса можно переобучить под себя — в проекте FSRS есть оптимизатор, ему нужна
история ответов, и она в карточках лежит.

### Набор по теме

«Создай карточки с неправильными глаголами» — это не одно слово, и под разбор
одного слова такая просьба не подходила: она уходила в обычную реплику, и кот
на неё просто болтал.

Тему кот не выдумывает и не сокращает: что попросили, то и уходит в промпт.
Ответ разбирается строками `english | перевод`, а не JSON — просить у модели на
процессоре скобки значит получить ошибку в скобках. Нумерацию, звёздочки и
«Вот список:» она всё равно приписывает, поэтому разбор их снимает: обещание
формата — это не гарантия формата.

Замерено на живой модели: пятнадцать неправильных глаголов за 23 секунды,
разобралось четырнадцать пар.

### Что кот замечает сам

Три фоновых чувства, которые кот держит, не спрашивая, и подмешивает в
собственные реплики только «если к месту» — иначе он зачитывал бы их вслух:

- **Сколько компьютер стоял выключенным.** Кот пишет отметку времени раз в
  минуту (`health.beat`), и разрыв между последней отметкой и стартом — это
  либо выключенный компьютер, либо закрытый кот; первого несравнимо больше.
  Показывается только первые десять минут после запуска: через полчаса «ты
  вернулся» — уже ложь. Точное «сколько был выключен» через journald было бы
  хрупким ради одной фразы.
- **Последние пять минут набранного.** Отдельный глобальный слушатель
  клавиатуры (`typed.py`), кольцо на пять минут, только в памяти — ни в
  дневник, ни в session.json, ни на диск. Backspace съедает символ, пробел и
  Enter кладутся как есть. Выключается, пока кот сам ждёт код или пароль в
  пузыре, и `_redact` выкидывает из выдачи похожее на секрет — длинный кусок с
  цифрой и символом, или очень длинный токен целиком. Это не гарантия
  (глобального «это поле пароля» в X11 нет), а разумный минимум для того, что
  хозяин включил сам.

### Английский по экрану

Дешёвый признак — вкладка или заголовок окна со словом english/англ/переводчик —
поднимает кота посмотреть на экран. Если модель со зрением подтверждает (первой
строкой `YES`), включается режим учёбы: снимок раз в минуту, пока это длится,
и каждый снимок продлевает режим ещё на несколько минут.

Со снимка кот забирает пары `english | перевод`, которые реально видны — так
слово, которое хозяин спросил у ассистента, само оказывается в колоде (набор
«английский»). Три фильтра против болтливой модели, вычитанные из живого
теста: **лицо — латиница**, **оборот — с кириллицей** (перевод, а не
английский заголовок), и **не длиннее короткой фразы** (не субтитр).

**Модель зрения проверялась на настоящем экране, и дешёвая победила.** iq2 на
экране с вопросом ассистенту вернул ровно `reason | причина, повод` за 12
секунд; большой `qwen2.5vl:32b` ошибся с `NO`, потратил 70 секунд и свалил в
кучу субтитры и названия видео. Поэтому по умолчанию читает iq2, а `vision_model`
в настройках — escape hatch, который редко того стоит.

### Кот и хобби

Позвать повторить — раз в шесть часов, и только когда хозяин на месте, ничем не
занят вплотную и никто ничего не говорил последнюю минуту. Тишина здесь важнее
напоминания: карточки, о которых спрашивают каждый час, перестают быть хобби и
становятся долгом.

Закрытое окно карточек — повод сказать что-нибудь про занятие, если в нём
что-то было. Молча закрытое окно занятием не считается.

### Сколько времени и куда

Считается по окну, которое **перед хозяином**, а не по запущенным процессам.
`app_since` рядом меряет, сколько живёт процесс, и свёрнутый на два часа
майнкрафт числился бы там двумя часами игры.

Два числа, потому что они отвечают на разные вопросы. Дневная сумма — то, что
кот может сказать вслух, и она попадает в промпт **только когда спросили**:
иначе кот объявлял бы итог сам, без повода. Непрерывный отрезок — то, по чему
решается, что пора размяться, и он обнуляется от переключения на другое, потому
что переключение и есть перерыв.

### Сжатие недель

Дневник растёт быстрее любого промпта. Закончившаяся неделя выжимается в
несколько предложений — «много играл в майнкрафт, кодил Мяумори, друзья звали в
дискорд», — и длинная память становится этими сводками, а не сотнями сырых
строк. Текущая неделя и последние дни не трогаются: сводка, написанная до конца
недели, устареет в тот же день. Ничего не удаляется — дневные файлы остаются на
диске, просто перестают быть тем, что читается.

## 8. Настройки

Окно из контекстного меню кота пишет в `settings.json`, и почти всё
применяется сразу: переключатели источников, пауза между репликами, модели,
имя и род хозяина. Ждут перезапуска только рост и скин — из роста считается вся
геометрия окна, а она строится один раз.

**Всё в одном окне.** Список машин и вход в телеграм жили отдельными окнами и
переехали внутрь: список правится на месте, поля редактора просто скрыты, пока
редактировать нечего, а ключ ssh выбирается файловым диалогом. Отдельное окно
ради четырёх полей — это одно окно лишнее.

Род хозяина — не косметика. В русском он слышен в каждом глаголе прошедшего
времени, и модель, не будучи предупреждённой, угадывает его сама и ошибается.

**Поле имени в настройках никто не заполнял.** Оно стояло там с самого начала,
и кот всю первую неделю звал хозяина «Хозяин» и путал род в каждом глаголе.
Теперь при первом запуске он спрашивает сам — в своём пузыре, тем же способом,
которым спрашивает код из телеграма: имя, «пришёл или пришла», и «расскажи о
себе». Третий ответ уходит в картотеку, а не в настройку: это то, что стоит
помнить, а не то, что переключают.

Признак первого запуска — **пустое имя**, а не только флаг: флаг появился позже
самой настройки, и хватать клавиатуру, чтобы спросить имя у того, кто его давно
вписал, — это не знакомство.

У плазмоида своя, штатная конфигурация Plasma (`config/main.xml` +
`configGeneral.qml`): размер, интервал опроса, притушивать ли лежанку без кота
и запускать ли кота кликом. Путь к `run.sh` лежанка берёт из файла, который кот
пишет при старте, — апплет не может знать, куда клонировали репозиторий.

Ловушка: настройка, которую ни разу не сохраняли, читается из QML как
`undefined`, а `Math.min(1.0, undefined)` — это `NaN`. Поэтому у каждого чтения
есть запасное значение прямо в QML, а не только умолчание в `main.xml`.

И вторая: `kpackagetool6 --upgrade`, которому дали голый id апплета, удаляет
установленную копию и не ставит новую — панель остаётся с виджетом, которого
больше нет. `install.sh` передаёт абсолютный путь и проверяет результат.

## 9. Телеграм

Не уведомления, а сам аккаунт: кот читает диалог и отвечает в нём. Это MTProto,
то есть Telethon — единственная необязательная зависимость проекта. Нет её —
функция объясняет, чего не хватает, остальной кот работает как работал.

**Вход делает хозяин, а не кот.** В настройках задаются api_id, api_hash и
номер. Всё остальное спрашивает сам кот — **в своём пузыре**:

```
    тебе пришёл код, проверь телеграм
    > 54321▌
```

Фраза печатается посимвольно, как будто он её сочиняет, но текст шаблонный:
модель тут не при чём. Мгновенно появившаяся строка читается как диалоговое
окно, та же строка, набранная по буквам, — как кот, который её говорит.

Код и облачный пароль вводятся туда же; пароль показывается точками. Ни номер,
ни код, ни пароль никуда не записываются — они уходят прямо в запрос Telethon.
Остаётся только файл сессии.

**Пока в пузыре ждут ответа, он модальный.** Кот замечает много всего, и любая
реплика — сменился трек, пришло уведомление, досмотрел экран — раньше отменяла
ожидание кода: захват клавиатуры отпускался посреди набора, а уже введённые
цифры выбрасывались. Второй, тихий вариант той же беды: `say()` перерисовывал
пузырь поверх вопроса, при этом нажатия продолжали приходить в невидимое поле.
Теперь, пока вопрос открыт, реплики отбрасываются, а пузырь не перерисовывает
никто. Отменить ожидание могут только Esc, таймаут и укладывание в лежанку.

**Как пузырь читает клавиатуру.** Окно кота — это `DOCK`, который намеренно
отказывается от фокуса, иначе он воровал бы его у настоящих окон. Поэтому не
фокус, а захват клавиатуры через `Gdk.Seat.grab`. Утёкший захват означал бы, что
хозяин не может печатать вообще нигде, поэтому он отпускается по Enter, по Esc,
по таймауту в три минуты, при укладывании в лежанку, при любой другой реплике и
при выходе.

То же самое из терминала, если так привычнее:

```bash
python3 -m mewmori.telegram login
```

Поручение выглядит так:

```
ответь лонеру что у меня нет таких денег
```

Разбирается регуляркой, а не моделью: глагол и адресат ловятся по форме,
остальное — смысл, и его сочиняет модель. Русский падеж адресата («лонеру» от
«Лонер») обходится сравнением по основе, а не целиком.

Дальше кот находит диалог, берёт из него последние реплики для контекста,
сочиняет сообщение от своего лица — «говорит mewmori, хозяин говорит, что…» с
кошачьим эмодзи — и **показывает точный текст с адресатом перед отправкой**.
Текст в этом окне можно править. Ничего не уходит другому человеку, пока это
окно не подтвердили; подтверждение отключается в настройках, если надоест.

Telethon — asyncio, GTK — нет, поэтому клиент живёт на отдельном потоке со
своим циклом событий, а ответы возвращаются колбэком, который вызывающий сам
кладёт на свой цикл.

## 10. Голос

Перенесено из отдельного демона `speak`, который делал то же самое, но
разговаривал с хозяином через всплывающие уведомления. Теперь у этого есть
лицо: кот поднимает уши, встаёт и показывает распознанное в пузыре, пока ты
говоришь.

| Что | Как | Что делает |
|---|---|---|
| Диктовка | зажать правый Alt | Печатает туда, где курсор, дописывая слова по ходу речи |
| Починка текста | два быстрых нажатия той же клавиши | Берёт поле целиком, чинит раскладку и опечатки через ollama, кладёт назад |
| Команды | Shift+Ctrl или обращение по имени | Музыка, окна, запуск программ |
| Вопрос вслух | зажать F1 | Уходит коту как обычная реплика — тот же характер, та же память |

**Микрофон выбирается явно.** Запись идёт через устройство `pulse`, а оно
следует за тем, что *системой* назначено по умолчанию, — здесь это оказался
пустой аналоговый вход на материнской плате, гудящий на −28 dBFS, пока
настоящий USB-микрофон стоял без дела. Кот слышал стену шума и не узнавал в ней
ничего, а выглядит это ровно как сломанные горячие клавиши: жмёшь аккорд,
говоришь, ничего не происходит.

`PULSE_SOURCE` подменяет умолчание **только для процесса кота**, поэтому выбор
микрофона в настройках не двигает его всем остальным. Рядом кнопка «Проверить»:
три секунды записи, пик и то, что услышал Whisper, — разница между «работает ли
оно?» и знанием.

**Кот отзывается на несколько имён** — «мяумори», «мяуми», «кот» — и совпадение
идёт по целым словам. Это не придирка: «кот» подстрокой ловится в «который»,
«скотч» и «работа», и кот отзывался бы на половину фраз в комнате. Падежное
окончание при этом допускается: «коту скажи» — это всё ещё обращение.

**Модель держится тёплой в процессе кота.** Отдельный интерпретатор на каждую
фразу стоил около шести секунд — терпимо для демона, невыносимо для того, кого
только что спросили.

**Одна блокировка на весь GPU.** Диктовка, слово-обращение и вопрос вслух
декодируют на одном контексте CTranslate2 из разных потоков, и два
пересекающихся `transcribe()` роняют процесс с «CUDA failed with error
unspecified launch failure». Флаги занятости мешают начать одновременно; не
пересечься помогает только мьютекс.

**Испорченный контекст CUDA ничего не роняет** — он просто делает все
последующие распознавания пустыми, навсегда и без единого симптома, кроме
«кот перестал слышать». Поэтому при такой ошибке процесс выходит сам.

**Однословный триггер срабатывает только в короткой фразе.** «Пауза» посреди
предложения — это слово, а не команда; в перенесённом коде эта разница
отсутствовала, и музыка вставала от любого упоминания.

**Открыть программу — одно правило, а не список.** Псевдонимы лежат в
`apps.CATALOGUE` рядом с тем, как программа опознаётся среди процессов, поэтому
новая строка там сразу и распознаётся, и открывается голосом.

Из перенесённого **не взят** запасной облачный бэкенд OpenRouter: обещание кота
в том, что наружу не уходит ничего, и тихий поход в сеть его бы нарушил.

### Чем это оплачено

Голос — единственная часть, которой нужны настоящие пакеты: `faster-whisper`,
`sounddevice`, `numpy`, `pynput`. Debian не даёт ставить их в системный питон,
поэтому нужен virtualenv, **обязательно** с `--system-site-packages`: без него
внутри не видно `gi`, и окна не будет вовсе. `run.sh` поэтому не верит имени
каталога, а проверяет каждого кандидата на `import gi` и берёт первого живого.

```bash
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r requirements.txt
```

Без этих пакетов кот запускается, рисует, говорит и всё замечает как прежде —
голосовая половина просто сообщает, чего ей не хватает.

**Видеопамять придётся делить.** Две модели ollama занимают почти все 12 ГБ, и
Whisper на карту уже не помещается — он падает на CPU (это предусмотрено и
работает, но медленно). Если голос нужен быстрым: модель поменьше в настройках,
либо более короткий `keep_alive` у ollama.

## 11. Окно кота

Обычное окно GTK3 с подсказкой типа `DOCK`, прозрачное (RGBA-visual),
без рамки, всегда сверху, на всех рабочих столах, не принимает фокус.

- **Клики ловит только сам кот** — `input_shape_combine_region` по его габаритам,
  остальное окно прозрачно для мыши насквозь.
- **Ходит по прямоугольнику** — прямоугольник считается из габаритов кота и
  рабочей области так, что ни одна его часть не выходит за экран.
- **Направление взгляда**: арт нарисован смотрящим влево (хвост справа от тела),
  поэтому движение вправо требует зеркального отражения.
- **Шрифт** пузыря регистрируется через собственный `FONTCONFIG_FILE` — в
  системные папки шрифтов ничего не ставится.

## 12. Запуск

```bash
./run.sh          # обычный старт, кот появляется на столе
./run.sh --bed    # старт спящим в лежанке
```

**Запустить кота могут трое** — автозапуск, лежанка, когда видит, что кота нет,
и человек из терминала, — и они гонятся. Двое котов дерутся за одно и то же имя
на шине: второй его отбирает, а первый продолжает ходить по столу, но с лежанкой
уже не разговаривает. Поэтому при старте кот сначала спрашивает у шины, не занято
ли `org.mewmori.Cat`, и молча выходит, если занято.

Автозапуск: `~/.config/autostart/mewmori.desktop` вызывает `run.sh --bed`.
Если через 25 секунд аплет так и не объявился ни в одной панели, кот выходит на
рабочий стол сам — иначе он остался бы невидимым и его нечем было бы разбудить.

Пересобрать спрайты лежанки после правки графики:

```bash
python3 tools/bake_bed.py
```

## 13. Проверки

```bash
python3 test_rig.py
```

Один файл, без фреймворков, проверяет то, что ломается молча: интерполяцию
ключевых кадров и per-key easing, аддитивность оверлеев, целостность стейт-машины
(все состояния ссылаются на существующие клипы), обрезку прозрачных полей,
прямоугольник хождения (включая второй монитор со смещением), фильтр рассуждений
в потоке токенов, отсев рекламы Spotify, разбор заголовка окна IDE и отсев
мусорных каталогов из дерева проекта.

Добавилось: разбор `/proc` в показания машины и пороги по ним, гистерезис жалоб
(одна и та же не повторяется, но возвращается после того, как прошла и снова
случилась), разбор блока `dbus-monitor` — включая то, что кнопки и подсказки
уведомления не должны попасть в его текст, — распаковка LZ4 всеми тремя путями
(литералы, обычная копия, перекрывающийся прогон), обрыв файла сессии, и
переходы состояний Claude Code: вопрос слышен всегда, короткий ход — нет.

Живые сценарии — лежанка, зрение, цикл присутствия, реакции на запуск программ —
проверялись отдельными скриптами против настоящей системы, потому что требуют
работающих plasmashell, ollama и D-Bus.
